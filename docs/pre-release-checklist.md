# Приёмка перед первым публичным релизом

Автоматические тесты проверяют API, права, миграции, MCP, SDK, поддельные IMAP/OAuth-ответы и локальную почту.
Они не заменяют живое согласие Google/Microsoft, доставку через интернет и запуск в приложении пользователя.
Ниже — задания владельцу проекта с проверяемым результатом. Пароли и токены в отчёт не вставлять.

## 1. Настоящий Gmail и письмо туда-обратно — обязательный минимум

Нужны отдельный тестовый Gmail и второй принадлежащий вам адрес для переписки. Не подключайте основной рабочий
ящик для первой проверки. Из checkout ядра, с Docker/Compose и uv:

```sh
uv run agentbox init --build --directory agentbox-gmail-check --port 18160 --mode mailbox --provider gmail
```

Если порт или каталог занят, выберите другой. Владелец сервиса настраивает Google OAuth по
[инструкции](mail-connection.md), задаёт параметры в приватном `.env` созданного стека и пересоздаёт API/worker.
Откройте выданную приватную ссылку и выберите «Подключить мой Gmail». Пароль вводится только у Google.
Пароль приложения не заменяет проверку этого сценария. Не присылайте пароль или полную ссылку.

- [ ] Подключение завершилось, появился ящик и файл `agentbox-gmail-check/agent.env`.
- [ ] Google запрашивает только идентификацию, чтение и отправку; полный доступ и изменение/удаление не запрашиваются.
- [ ] Существующая переписка не импортировалась: по умолчанию синхронизируются новые входящие письма.
- [ ] В консоли авторизовались операторским ключом из `operator.json`; агенту передаётся только `agent.env`.
- [ ] Через MCP или SDK создано письмо на ваш второй адрес. С ключом `review` оно остаётся `pending_approval`
  и ещё не приходит получателю. Агент не может одобрить его сам.
- [ ] После одобрения человеком письмо действительно пришло во второй ящик. Проверен отправитель.
  Статусы `queued` и `provider_accepted` сами по себе не доказывают доставку.
- [ ] Со второго ящика отправлен ответ кнопкой «Ответить», с текстом и маленьким TXT/CSV-вложением.
  Ответ виден в AgentBox, связан с исходным письмом; вложение скачивается без изменения содержимого.
- [ ] Созданное ожидание ответа возвращает `matched`, в том числе после перезапуска процесса агента.
- [ ] Пауза останавливает последующие синхронизации; после возобновления новое письмо подтягивается.
  Уже выполняющийся синк может закончиться. После отключения подключения следующие письма не импортируются.

## 2. Настоящий агент — минимум один клиент, затем оба целевых

В [гайде](agents.md#2-add-mcp-and-the-skill) есть шаблоны OpenClaw/Hermes и остальных клиентов. До публикации
v0.2.0 используйте абсолютный локальный путь `sdk/python[mcp]`, а не ещё не опубликованный тег или пакет.
Добавляйте конфиг к существующему, не заменяйте весь файл. Не помещайте ключ в общий репозиторий.

- [ ] MCP стартует без ручной установки Python SDK; инструменты отображаются.
- [ ] Ключ ограничен одним тестовым ящиком; `list_inboxes` не показывает чужих ящиков.
- [ ] Задание «Подготовь письмо на МОЙ_ВТОРОЙ_АДРЕС с темой AgentBox acceptance; я одобрю отправку»
  приводит к черновику, а не к запросу администраторского ключа или обходу одобрения.
- [ ] После вашего одобрения и ответа агент читает ответ в том же треде.
- [ ] После перезапуска клиента агент продолжает ожидание по сохранённому message ID и не отправляет письмо заново.
- [ ] Отдельно отмечено, в каких версиях OpenClaw и Hermes это действительно проверено. Успех одного клиента
  не считать проверкой второго.

## 3. Google/Microsoft OAuth — до объявления поддержки соответствующего провайдера

Нужны принадлежащие вам OAuth-приложения и тестовые ящики. Настройка переменных и callback URL описана в
[контракте подключения](agent-contract.md#browser-connection-and-oauth). Секреты вводятся локально или в менеджер
секретов, не в чат. Для удалённого сервера нужен HTTPS. Не включайте неподтверждённый способ входа в рекламу.

- [ ] Согласие в браузере успешно, адрес подключённого ящика верный. Проверены и отмена согласия, и повторный вход.
- [ ] После истечения access token синхронизация и отправка продолжаются без повторного входа:
  это проверка refresh token, а не только первоначального подключения.
- [ ] Отзыв доступа в аккаунте провайдера приводит к понятной ошибке подключения; новое подключение работает.
- [ ] Microsoft 365 проверен именно через OAuth; пароль приложения не считать рабочим способом входа.

## 4. Inbound-вебхуки — по каждому провайдеру, которого объявляем поддержанным

Нужны тестовый поддомен, HTTPS-сервер и аккаунт Mailgun, SendGrid или Postmark. Не меняйте MX основного рабочего
домена. Следуйте [инструкции конкретного провайдера](inbound-webhooks.md); исходящая доставка настраивается отдельно.

- [ ] При отключённом SMTP edge AgentBox получает внешнее письмо через HTTPS: текст, тред и вложение корректны.
- [ ] Повторная доставка того же payload через средство replay провайдера не создаёт второе письмо.
- [ ] Неверная подпись/учётные данные отклоняются; адрес другой организации не получает письмо через этот endpoint.
- [ ] После удаления endpoint новые обращения отклоняются. Секреты и полные callback URL отсутствуют в отчёте.

## 5. Публичная установка и каталоги — после публикации

Это отдельные внешние действия, а не результат локального коммита. Порядок и необходимые права —
в [release.md](release.md). Сначала push проверенных коммитов и зелёный CI обоих репозиториев, затем
настройка прав на релиз, публикация SDK/образа и только после этого установка из реестров.

- [ ] На чистой машине вне checkout устанавливаются `agentbox-sdk[mcp]==0.2.0` и `@agentbox/sdk@0.2.0`.
- [ ] Опубликованный Docker-образ запускается без локальной сборки, мастер проходит demo roundtrip.
- [ ] Опубликованный MCPB устанавливается; SDK скачивается из реестра, инструменты работают с ограниченным ключом.
- [ ] ZIP/MCPB в GitHub Release соответствуют SHA-256 в `server.json`; публикация в каждом каталоге подтверждена
  отдельно, а не только наличием подготовленного манифеста.

## Как сообщить результат

Для каждого пункта: `PASS / FAIL / NOT RUN`, клиент и версия, провайдер, время проверки, ожидаемый и фактический
результат. Для ошибки API — `error.code` и `request_id`; для почты — ID сообщения AgentBox и этап сбоя.
Скриншоты допустимы без ключей, приватных ссылок и содержимого посторонних писем.

После проверки отключите тестовые подключения и отзовите лишние ключи. Локальный проверочный стек останавливается
командой `docker compose --project-directory agentbox-gmail-check down`: контейнеры удалятся, тома и приватные
конфиги сохранятся. Основной стек эта команда не затрагивает.
